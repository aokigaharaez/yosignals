# Signal Lab — Telegram Mini App

Telegram Mini App для нескольких владельцев: реальные рыночные свечи,
локальная ML-модель, прогнозы CALL / PUT, оценка шанса, график и общий журнал.
Анализы, сигналы и таймеры находятся внутри приложения. Бот даёт кнопку входа.

## Обновление работающего Railway-сервиса до v5.0

Локальные изменения сами по себе не обновляют Railway. Замените файлы приложения
в подключённом GitHub-репозитории и дождитесь успешного нового Deploy.
Root Directory остаётся `/telegram_signal_app`, команда — `python -m app.main`.
Не создавайте вторую вложенную папку `telegram_signal_app/telegram_signal_app`.

После обновления адрес `/health` должен возвращать `version: "5.0"` и
`delivery: "miniapp"`. Закройте Mini App полностью, отправьте боту `/start`
и откройте снова: в шапке появится **MINI APP · v5.0**, в меню — **Сигналы** и **Доступ**.
Старые сообщения в чате остаются; новые анализы бот туда не отправляет.
Если новые сообщения со старым форматом продолжаются, проверьте, не запущена ли
ещё старая копия на компьютере или в другом Railway-сервисе.

Для сохранения истории и владельцев нужен Railway Volume, подключённый к `/data`,
и `DB_PATH=/data/signals.db`. Перед обновлением сохраните резервную копию существующей
базы. При первом запуске её журнал переносится без удаления исходной таблицы.

## Быстрый запуск на этом компьютере

Зависимости уже установлены в `.venv`. Откройте PowerShell в папке проекта:

```powershell
.\.venv\Scripts\python.exe -m app.main
```

Или дважды нажмите `start.bat`. Не закрывайте окно сервера.
Откройте http://127.0.0.1:8000. Остановка — Ctrl+C в окне сервера.

При старте выводятся этапы [1/3], [2/3], [3/3]. Дождитесь строки
\`Uvicorn running on http://127.0.0.1:8000\`; до неё Ctrl+C прервёт запуск.
Бот и библиотеки ИИ загружаются в фоне, после открытия веб-сервера.
Пока модель готовится, интерфейс показывает «Подготовка анализа».
Первый запуск из папки OneDrive может быть медленнее из-за чтения файлов библиотек.

Если нужен только просмотр без подключения к Telegram:

```powershell
$env:BOT_ENABLED="false"
.\.venv\Scripts\python.exe -m app.main
```

Чтобы снова включить бота в том же PowerShell: `Remove-Item Env:BOT_ENABLED`,
затем запустите сервер заново.

## Настройки .env

Существующие значения сохранены. Добавленные пустые поля нужно заполнить:

```dotenv
BOT_TOKEN=токен_вашего_бота
OWNER_TELEGRAM_ID=ваш_числовой_Telegram_ID
TWELVE_DATA_API_KEY=ваш_ключ_Twelve_Data
WEBAPP_URL=https://ваш-домен.example
```

Не публикуйте `.env`. В прежнем `.env.example` был токен: перевыпустите его через
BotFather и обновите `BOT_TOKEN`. Из нового шаблона секрет удалён.

Без Twelve Data работают публичные криптовалютные данные Binance, если источник
доступен в вашей сети. Валютные пары показывают состояние «Нужен API-ключ».
Никаких случайных котировок или подставных прогнозов приложение не создаёт.

После изменения `.env` требуется перезапуск сервера.

В Railway эти значения задаются в **Variables**. Несколько основных владельцев:
`OWNER_TELEGRAM_ID=123456789,987654321`. Также поддерживается
`OWNER_TELEGRAM_IDS`; если заполнены обе переменные, списки объединяются.
Одиночный старый `OWNER_TELEGRAM_ID` продолжает работать.

## Владельцы и раздел «Доступ»

1. Откройте Mini App под одним из основных владельцев.
2. Перейдите в **Доступ**, введите Telegram ID и нажмите **Добавить владельца**.
3. Новый владелец отправляет боту `/start` и открывает Mini App.
   Если ID неизвестен, до выдачи доступа команда `/start` показывает человеку его ID.
4. Кнопка **Отозвать доступ** блокирует следующие запросы удалённого владельца
   и вход через бота. Его уже сохранённые анализы остаются в общем журнале.

Все владельцы равноправны: общий журнал, общий автоанализ, управление владельцами.
Дополнительные владельцы хранятся в SQLite; перезапуск для их изменения не нужен.
Ключи поставщика и токен бота через API не выдаются.
Основные ID из Variables нельзя удалить в Mini App; собственный доступ в текущей
сессии также нельзя отозвать. Основной список меняется в Variables с перезапуском.

## Открытие внутри Telegram

1. Разместите приложение на сервере с публичным HTTPS-адресом или подключите
   HTTPS-туннель к локальному порту 8000. Локальный адрес 127.0.0.1 нельзя использовать
   как WEBAPP_URL: Telegram на телефоне не сможет к нему подключиться.
2. Укажите этот HTTPS-адрес в WEBAPP_URL.
3. Для сервера за reverse proxy установите LOCAL_PREVIEW=false.
   Если нужен внешний bind, задайте HOST=0.0.0.0 и ограничьте порт на уровне сети:
   пользователи должны обращаться через HTTPS-прокси.
4. Запустите один процесс `python -m app.main`. Он обслуживает веб-приложение,
   polling бота и планировщик. Несколько worker-процессов не поддерживаются.
5. Отправьте боту /start в личном чате и нажмите «Открыть Signal Lab».
   При подключении бот также задаёт кнопку меню Mini App.

Доступ разрешён владельцам из Variables и базы. Сервер проверяет HMAC-подпись initData
и срок сессии Telegram. LOCAL_PREVIEW разрешает только локальный просмотр рынка;
журнал, запись результатов и автоанализ требуют Telegram-авторизации.
После истечения сессии закройте и откройте Mini App заново.

## Развёртывание на Railway

Если в журнале сборки Railpack видны только папка `telegram_signal_app/` и
`README.md`, выбрана неверная корневая папка. В GitHub файлы приложения находятся
на один уровень глубже, чем ожидает Railway.

1. Обновите содержимое `telegram_signal_app/` в GitHub файлами этого проекта,
   включая `Dockerfile`, `.dockerignore`, `.python-version`, `requirements.txt`
   и папку `app/`. Не загружайте `.env`, `.venv` или локальную базу данных.
2. В сервисе Railway откройте **Settings → Source → Root Directory** и задайте
   `/telegram_signal_app`. Если `requirements.txt`, `Dockerfile` и `app/` лежат
   прямо в корне GitHub-репозитория, оставьте корневую папку `/`.
3. Railway автоматически использует `Dockerfile` из выбранной папки. Очистите
   старые пользовательские Build Command / Start Command, если они были заданы.
   В образе команда запуска уже настроена: `python -m app.main`.
4. В **Variables** задайте `BOT_TOKEN`, `OWNER_TELEGRAM_ID`,
   `TWELVE_DATA_API_KEY`, `HOST=0.0.0.0`, `LOCAL_PREVIEW=false`.
   `PORT` предоставляет Railway; приложение читает его автоматически.
5. Добавьте постоянный **Volume** с Mount Path `/data` и задайте
   `DB_PATH=/data/signals.db`. Без Volume журнал исчезнет при пересоздании контейнера.
6. В **Settings → Deploy** задайте Healthcheck Path `/health`.
   Оставьте одну реплику: несколько экземпляров будут конфликтовать за polling бота.
7. Примените настройки и запустите **Deploy**. После успешного запуска откройте
   **Settings → Networking → Public Networking → Generate Domain**.
8. Скопируйте полученный HTTPS-адрес в `WEBAPP_URL` и примените изменение.
   Затем отправьте боту `/start` и откройте приложение его кнопкой.

Публичная страница открывается в браузере, но защищённые данные и функции доступны
только из Telegram владельцу бота. Сообщение «Откройте приложение через Telegram»
в обычном браузере после развёртывания ожидаемо.

Быстрое исправление текущей ошибки без Dockerfile: задайте Root Directory
`/telegram_signal_app`, Start Command `python -m app.main`, `HOST=0.0.0.0`
и `LOCAL_PREVIEW=false`, затем повторите Deploy. Это исправляет обнаружение
Python-проекта; если далее появится другая ошибка, изучите новый Build Log.

Документация: [корневая папка Railway](https://docs.railway.com/deployments/monorepo),
[сборка Dockerfile](https://docs.railway.com/builds/dockerfiles),
[проверка здоровья и PORT](https://docs.railway.com/deployments/healthchecks).

## Анализы и сигналы в Mini App

- **Обзор рынка → Получить сигнал** — запросить расчёт для выбранных актива
  и экспирации. Кнопка доступна в любое время; нужны свежие данные поставщика.
- **Автоанализ** — проверять выбранную пару примерно раз в минуту и добавлять
  результаты в ленту Mini App, даже когда приложение закрыто.
- **Сигналы** — общий журнал с направлением, оценкой шанса, временем входа,
  таймером закрытия и ручной отметкой результата.
- `/start`, `/app` и прежние `/analyze`, `/watch`, `/stop`, `/stats`
  теперь только показывают кнопку Mini App. Включать и выключать автоанализ
  нужно переключателем в приложении.

В открытом Mini App есть уведомления о новых сигналах и времени входа/закрытия.
В закрытое приложение push-уведомления и сообщения в чат не отправляются;
накопленные сигналы видны при следующем открытии. Автоанализ не зависит от polling
бота, но требует работающего сервера. Лента обновляется каждые 15 секунд.
Приложение не размещает сделки.

Активы: EURUSD, GBPUSD, USDJPY, AUDUSD, EURJPY, BTCUSDT, ETHUSDT.
Экспирации: 1, 3, 5, 15 минут. На длинных экспирациях меньше независимых примеров,
поэтому чаще показывается пометка о слабом качестве.
Вне часов валютного рынка доступны BTC/USDT и ETH/USDT при доступности Binance.
Для закрытого рынка, устаревших данных или исчерпанной квоты прогноз не выдумывается.

Раньше слабая проверка модели и последние 10 секунд перед входом превращали
ответ в «Ждать». Теперь слабый CALL/PUT виден с пояснением. Поздний запрос
переносит вход на следующую минутную границу, оставляющую не меньше 10 секунд,
и пересчитывает модель для соответствующей задержки входа.

## Рыночные источники

- **Twelve Data**: минутные OHLC валютных пар, до 1 500 свечей на запрос.
  Требуются API-ключ и соответствующий доступ в тарифе. Проверьте задержку данных
  и условия использования/отображения котировок вашего тарифа.
- **Binance Spot**: BTC/USDT и ETH/USDT через публичный market-data API;
  две страницы истории до 1 500 свечей, ключ не нужен.

Кеш по активу обновляется с новой минутой, максимум через 60 секунд. Ошибки и ограничения провайдера
кешируются на 60 секунд. Автоанализ одной валютной пары может потреблять около
60 запросов в час / 1 440 в сутки; лимиты тарифа могут быть меньше.
Переключение пар расходует дополнительные запросы.

Используются только закрытые свечи. Неверные OHLC, дубликаты, пропуски,
недостаточная история и устаревшие данные обрабатываются явно.
Прогноз недоступен, когда котировки старше MAX_DATA_AGE_SECONDS (90 по умолчанию).
Если расчёт занял слишком долго, время и свежесть данных проверяются повторно.

Цены — внешние рыночные данные, а не поток Pocket Option. Пары к USDT нельзя
считать идентичными брокерским инструментам к USD. Перед использованием
нужно проверить наличие актива и сопоставимость цен. **OTC Pocket Option не
поддерживается:** для него нужен отдельный подтверждённый источник котировок.

## ML-модель

Это адаптивная ML-модель scikit-learn, работающая на сервере;
ключ OpenAI или другой LLM не нужен.

- Модель обучается отдельно для каждой пары и экспирации.
- До 40 причинных признаков: исходные 10 признаков плюс движение, волатильность,
  положение в диапазоне, отклонение от средней и направленность за 5/15/30/60/120 минут,
  тени свечей, положение закрытия и циклическое время суток UTC.
- Первые 60% пригодных примеров используются для выбора и обучения модели.
  Кандидаты: прежняя линейная модель на 10 признаках, линейная на 40 признаках, более регуляризованная линейная модель,
  HistGradientBoosting, Extra Trees и ансамбль линейной модели/бустинга/деревьев.
  Выбор проходит на двух расширяющихся временных участках внутри этих 60%,
  по log loss с удалением пересекающихся целей. Для замены требуется улучшение
  log loss минимум на 0.005; при недостатке истории остаётся прежняя модель.
  После выбора победитель обучается на всём обучающем участке.
  Следующие 20% используются для калибровки, последние 20% — для проверки.
  На обеих границах удаляются пересекающиеся цели; примеры калибровки и проверки
  не перекрываются по горизонту. Контрольные исходы не входят в калибровку.
- В `validation.model_selection` сохраняются выбранная модель, число внутренних
  проверок и log loss кандидатов. Имя выбранной модели показывается в Mini App.
  Проценты не повышаются искусственно, слабое качество остаётся явно отмеченным.
- Обучающие цели используют ту же задержку до входа, что и текущий прогноз:
  обычно одну минуту от закрытия последней свечи, при позднем запросе — две.
- На калибровочном участке прогнозы группируются по уверенности в интервалы
  шириной 10 процентных пунктов. При 30+ примерах в текущей группе процент —
  сглаженная доля успехов `(wins+1)/(n+2)`; показывается исторический интервал
  Уилсона 95%. Ничьи не считаются выигрышами; при обучении направления они исключены.
- Если примеров меньше 30, используется предварительная вероятность модели
  с поправкой на долю ничьих. Она явно обозначена как некалиброванная.
- Порог MODEL_MIN_SCORE (60%), контрольная точность MODEL_MIN_VALIDATION (54%),
  преимущество над постоянным прогнозом и число сильных примеров определяют
  метку качества. Они не скрывают слабое направление. Недостаток истории,
  разрывы последних свечей или отсутствие обоих классов дают «Нет прогноза».

Процент оценивает успешность направления на внешних котировках.
**Это не подтверждённая вероятность выигрыша сделки в Pocket Option**:
выплата брокера, исполнение и отличия котировок не учтены. Исторический интервал
отражает неопределённость прошлой доли успехов и не гарантирует будущий результат.
Маленькая недавняя выборка и изменения рынка ограничивают надёжность даже
калиброванной оценки. Доходность стратегии не доказана.

## Журнал и сохранность данных

Новые анализы хранятся в analysis_runs_v2; прежняя analysis_runs копируется
один раз с сохранением ID и результатов. Исходные таблицы analysis_runs и signals сохранены.
Случайные demo-сигналы и ручное создание из старой версии удалены из интерфейса
и команд. Старые результаты не смешиваются со статистикой ML.

Повторный анализ одной свечи, пары, экспирации и времени входа не создаёт дубликат.
Перенос входа на новую минуту сохраняется отдельной записью.
WIN/LOSS/DRAW можно отметить один раз после закрытия направленного сигнала.
Источник результата — user_reported: это отметка пользователя, не проверка брокера.
Журнал общий для всех владельцев; в локальном просмотре он недоступен.

## Установка с нуля

Нужен Python 3.12+ (проверено на Python 3.14 в Windows).

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# Заполните .env. Не перезаписывайте уже настроенный файл.
.\.venv\Scripts\python.exe -m app.main
```

В Linux используйте `python3 -m venv .venv` и `.venv/bin/python`.
SQLite-файл должен храниться на постоянном диске. Для резервной копии остановите
сервер и сохраните файл БД. Не запускайте несколько копий сервера с одним токеном.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
node --check app/static/app.js
```

Тесты проверяют подписи и срок Telegram-сессий, права владельцев, выдачу и отзыв
доступа, защиту локального просмотра, миграцию журнала, отсутствие сигналов в чате,
кеш и лимиты источника, причинность признаков, разделение калибровки и проверки,
перенос времени входа, слабые прогнозы, устаревшие данные и автоанализ без polling.

## Выбор ML Model / GPT (v2.6)

В карточке «ИИ-анализ» выберите «Модель анализа»: ML Model или GPT. В режиме GPT
выберите Sol, Luna или Astra и нажмите «Получить сигнал». GPT самостоятельно анализирует
последние 30 свечей и технические индикаторы; ML-прогноз и его вероятность не передаются.
GPT выбирает CALL/PUT/WAIT и объясняет причины и риски. Сервер задаёт время входа с запасом
на запрос OpenAI. Поздний ответ или устаревшие данные превращаются в WAIT.
GPT-прогноз сохраняется в общем журнале с названием модели, отдельно от ML для того же
актива и времени. Процент выигрыша и историческая точность GPT ещё не откалиброваны.
Автоанализ в фоне использует ML Model. В открытом Mini App GPT обновляется автоматически при включённом «Обновлять анализ автоматически», с API-ключом на сервере.

Для подключения добавьте `OPENAI_API_KEY` в Railway Variables и выполните Deploy.
Ключ хранится на сервере; API оплачивается отдельно от подписки ChatGPT. Проверка `/health`
должна показывать `5.0`. Модель и режим сохраняются на устройстве. Доступ к модели зависит
от API-проекта. Один GPT-запрос за минуту для каждого владельца, одновременно один на сервер.
Запросы выполняются через Responses API со `store=false`. Отказы провайдера показываются
в Mini App без переключения на другую модель. Telegram ID и секреты в OpenAI не передаются.

## Постоянный анализ и время сделки (v2.7)

Последний прогноз остаётся на экране при задержке поставщика, завершении времени входа
или экспирации. Отметки показывают давность анализа и данных; устаревший прогноз не
выдаётся за свежий. Котировки проверяются каждые 15 секунд, включая ожидание GPT.
Источники предоставляют закрытые минутные свечи: это не поток отдельных тиков.
ML автоматически обновляется по новым свечам. GPT запрашивается раз в 65 секунд,
пока обзор видим и включён «Обновлять анализ автоматически»; каждый запрос оплачивается
из OpenAI API-баланса. Снимите галочку, чтобы остановить автоматические GPT-запросы.
В скрытом приложении платные запросы не запускаются.

В «Время открытия сделки» выберите ближайшее доступное время или конкретную дату
и время в часовом поясе приложения. Точность — одна минута, допустим вход минимум через
10 секунд и в пределах следующих 24 часов. «Своя экспирация» принимает 1–60 минут.
Сервер учитывает выбранное время в горизонте ML-обучения и в задании GPT; время закрытия
равно времени входа плюс экспирация. Ответ GPT не сдвигает заданное пользователем время.
Для далёкого входа или длинной экспирации истории может не хватить: показывается причина.
Рынок может закрыться, источник — задержать свечи или исчерпать лимит; приложение сохраняет
последний анализ, показывает состояние и повторяет запросы, но не создаёт новые цены.
Время сделки задаёт параметры прогноза; приложение не открывает сделки у брокера.

## Короткий прогноз и ограничение ожидания (v2.8)

Главная карточка показывает крупный CALL / ВВЕРХ или PUT / ВНИЗ. Объяснение скрыто
в раскрываемом блоке «Почему такой прогноз». Для отсутствующих или устаревших данных
показывается «НЕТ СИГНАЛА» с причиной, направление не подставляется случайно.
Luna стоит первой в списке для быстрого ответа; сохранённый выбор модели применяется.
Для Luna в режиме сигнала отключено дополнительное рассуждение; Sol и Astra используют low.
GPT возвращает компактный JSON с направлением, короткой причиной и максимум двумя рисками.
Общий срок ожидания GPT — 25 секунд (получение котировок выполняется до запроса отдельно).
Если OpenAI не ответил, приложение показывает таймаут. Модель не подменяется автоматически.
В течение 45 секунд одинаковый завершённый GPT-прогноз для тех же свечей, модели, входа
и владельца повторно отдаётся из памяти без нового платного запроса. Доступ к рыночному
снимку GPT не ждёт блокировки обучения ML. Отсчёт длительности виден в карточке; ошибки
автообновления остаются в статусе. Скорость реального OpenAI-запроса зависит от провайдера.

## Задержка валютных свечей и состояния GPT (v2.9)

Для Forex применяется `FOREX_MAX_DATA_AGE_SECONDS=180` (допустимое значение 60–300).
Обычный `MAX_DATA_AGE_SECONDS` продолжает задавать предел для криптовалют.
Предел валютных данных учитывает задержку публикации минутных свечей Twelve Data.
Возраст больше 90 секунд явно отмечается как задержка источника, добавляется риск
предварительного прогноза. Предел не изменяет время реальных свечей: старые данные
всё равно блокируют новый прогноз. GPT получает EMA 9/21, RSI 14 и ATR 14,
которые вычисляются без запуска или ожидания ML.

«Запросите GPT-прогноз» означает, что загружены свечи, но GPT ещё не был вызван.
«Получаем прогноз GPT» означает выполняющийся запрос. Ошибка ключа/лимита/провайдера,
устаревшие данные и прошедшее время входа показываются разными состояниями.
Если сама модель вернула WAIT, её причина раскрывается автоматически.
Сервер сохраняет raw_direction и forecast_state для проверки, не превращая ошибку в прогноз.
Проверка UI: из папки приложения `node tests/frontend_gpt.cjs` проверяет, что CALL
не пропадает после обновления графика во время и после GPT-запроса.


## ML v4: история, обучение и строгий отбор

- Реальные закрытые свечи сохраняются в `market_candles` той же SQLite-базы.
  Архив ограничен `MODEL_HISTORY_LIMIT=20000` свечей на актив. Для сохранения между
  деплоями Railway нужен Volume `/data` и `DB_PATH=/data/signals.db`.
- При первом запросе криптовалюты фоновой задачей загружается до
  `CRYPTO_BACKFILL_CANDLES=10000` свечей Binance. Первый ответ использует доступную
  историю, следующие обновления подключают архив. Ошибка загрузки старых свечей
  не останавливает актуальные котировки. При перезапуске архив используется снова.
- Валютная история накапливается из обычных ответов Twelve Data при запросах
  и включённом автоанализе. Дополнительные платные запросы истории не выполняются.
  Непросматриваемые пары не опрашиваются; пропуски не заполняются случайными данными.
- Сравниваются шесть вариантов модели на двух последовательных внутренних
  проверках, затем выбранный вариант обучается на обучающем участке. Скейлеры
  обучаются только на соответствующем прошлом, рандомизация моделей фиксирована.
- Признаки охватывают последние 120 минут; цели с разрывами истории исключаются.
  Актуальные прогнозы считаются на новых свечах, а модель переобучается раз в
  `MODEL_RETRAIN_SECONDS=600` секунд при очередном анализе. Сильное увеличение
  доступной истории запускает обучение раньше. Пара/экспирация/задержка входа
  имеют отдельные модели. После перезапуска модели обучаются заново из архива;
  небезопасные pickle-файлы не загружаются. В памяти ограничено 32 комбинации.
- Флажок **«Только сигналы с проверенной точностью около 80%»** включает строгий
  отбор в интерфейсе и ручном анализе. Для автоанализа режим записывается на сервере
  при включении/изменении настройки. Обычный режим сохраняет слабые CALL/PUT с отметкой.
- Порог уверенности выбирается только на калибровочном участке. Требуются минимум
  100 независимых калибровочных примеров, доля побед не ниже цели 80% и нижняя граница
  интервала Уилсона 95% не ниже 60%. Замороженный порог проверяется на следующем,
  независимом участке: минимум 50 отобранных примеров, не менее 80% успеха,
  нижняя граница не ниже 60%, последние отобранные примеры не ниже 70% успеха.
  Текущий прогноз также должен иметь достаточную калибровку именно в своей группе.
- При невыполнении условий строгий режим показывает отсутствие подтверждённого
  сигнала и сохраняет предварительное направление отдельно. Проценты не повышаются
  искусственно. Цель 80% не является обещанием будущего результата, даже после
  прохождения исторической проверки. Повторные проверки не исключают переобучение.
- Интерфейс показывает объём обучения, выбранную модель, точность строгого отбора,
  число проверочных сигналов и покрытие: какой процент прогнозов прошёл отбор.

Для повторяемой проверки сохранённой истории на трёх временных участках:

```powershell
python -m app.evaluate --db signals.db --symbol EURUSD --expiry 3 --output eurusd-report.json
```

Команда читает архив и не изменяет модель приложения, настройки или сделки.
При недостатке 1500 свечей отчёт не содержит временных проверок.
Результаты реальной проверки v4 сохранены в `tests/ML_V4_COMPARISON.json`.
В сравнении v3 использовала 30 минут разогрева, v4 — 120 минут: контрольные участки
немного отличаются. Это сравнение протоколов, не точное сравнение на одинаковых целях.


## EUR/USD: отдельное обучение и вероятность (v4.1)

При открытии Mini App выбран EUR/USD. Отсутствие ключа Twelve Data показывает
ошибку валютного подключения; приложение не переключается автоматически на BTC.
Каждая модель и её кеш имеют ключ `(symbol, expiry, entry_delay)`. Архивы свечей
изолированы по символу. Процент EUR/USD не использует результаты BTC, ETH или GBP/USD.

`FOREX_HISTORY_CANDLES=5000` задаёт глубину одного запроса Twelve Data. Возвращённая
пара проверяется по `meta.symbol`, если поле предоставлено источником; ответ с другой
парой отклоняется. В отчётах вероятности, проверки и обучения сохраняются символ,
источник, экспирация и задержка входа. Интерфейс явно показывает пару возле процента
и статистики. Число независимо проверенных прогнозов зависит от экспирации.

Реальная проверка EUR/USD на 5000 закрытых свечах Twelve Data сохранена в
`tests/EURUSD_ML_COMPARISON.json`: контрольная точность 56.1% / 50.4% / 52.8%
для экспираций 1 / 3 / 5 минут. Калиброванная оценка текущего прогноза в том же
срезе составила 50.4% / 48.1% / 50.3%; это другая метрика, зависящая от группы
похожих прогнозов. Строгая цель 80% не подтверждена ни для одного из этих прогнозов.
Цифры относятся к этому участку истории и изменяются при обновлении данных.
Результаты внешних котировок не являются проверкой исполнения в Pocket Option.

Для проверки пары в сохранённом архиве `app.evaluate` теперь также выбирает
EURUSD по умолчанию. Глубина валютного запроса подтверждена
[документацией Twelve Data](https://support.twelvedata.com/en/articles/5656039-how-to-get-historical-prices).


## ML v5: исследование цели 70% для EUR/USD

**70% на независимой истории не достигнуты.** Изменение целевого порога не меняет
измеренную точность и не обеспечивает заявленную вероятность следующей сделки.

Добавлены четыре варианта регуляризации/сложности: линейная C=0.002,
бустинг на 3 и 15 листьях и Extra Trees глубиной 4. Теперь 10 вариантов модели
сравниваются на трёх расширяющихся участках обучающей истории. Последняя проверка
не используется для выбора победителя. Старая линейная модель остаётся кандидатом.

Дополнительная модель успешности прогноза обучается на предсказаниях, полученных
вне обучающих участков базовой модели, но внутри общих обучающих 60% истории.
Контекст включает рыночные признаки, направление и уверенность базовой модели.
Кандидаты: регуляризованная линейная модель и бустинг. Внутренняя хронологическая
проверка требует улучшения Brier минимум 0.005 и AUC выше 0.55, иначе дополнительная
модель отключается. Контрольные исходы внешних 20% не участвуют в этой процедуре.

Строгий отбор сравнивает 72 политики на калибровке: девять порогов от 0.50 до 0.90
и восемь контекстов (все прогнозы, тренд, диапазон, крупная/маленькая свеча,
фиксированные окна UTC для Лондона, США, Азии). Это часовые окна, а не точный календарь
биржевых сессий с учётом переходов времени. Выбирается политика с наибольшим покрытием,
подтвердившая целевую долю побед на калибровке. Та же политика затем один раз проверяется
на независимом контрольном участке; по его результатам другая политика не выбирается.
Процент для соответствующего контекста калибруется по той же отобранной группе.

Новые значения по умолчанию:

```dotenv
MODEL_TARGET_WIN_RATE=0.70
MODEL_MIN_CALIBRATION_SAMPLES=150
MODEL_MIN_TEST_SIGNALS=100
FOREX_BACKFILL_CANDLES=20000
```

Если Railway уже содержит другие значения этих переменных, они имеют приоритет.
Требуются не менее 150 отобранных калибровочных примеров и 100 контрольных,
не менее 70% побед на обоих участках, нижняя граница интервала Уилсона 95% от 60%
и не менее 60% побед на последней половине отобранной контрольной выборки.
Текущий прогноз должен удовлетворять замороженной политике и своей калибровке.
Строгий режим блокирует неподтверждённые прогнозы; обычный продолжает показывать слабые.

Для EUR/USD архив при первом запросе расширяется в фоне до 20000 свечей: до трёх
дополнительных исторических запросов Twelve Data по 5000 записей с `end_date`.
Это расходует квоту API. Другие валютные пары используют обычное накопление.
Ошибка исторического запроса оставляет доступными свежие котировки. База хранится
в том же Railway Volume; ключи в архив не записываются.

Сравнение большого числа вариантов занимает десятки секунд, поэтому обучение теперь
идёт в фоне с одной активной задачей и максимум двумя ожидающими/активными задачами.
Первые запросы возвращают котировки и статус подготовки; сохранить фиктивный прогноз
во время обучения нельзя. После обучения используются свежие свечи и готовая модель.
При переобучении текущая готовая модель остаётся доступной до атомарной замены.

Результаты исследования записаны в двух отчётах:

- `tests/EURUSD_ML_V5_RESEARCH.json`: первая фаза без дополнительной модели успеха,
  22000 свечей из архива 30000, последние 8000 исключены. Для экспирации 1 минута
  калибровка отбора показала 70.9%, контроль — 62.0% на 418 прогнозах,
  интервал 95% 57.2–66.5%, покрытие 19.1%. Строгая проверка не пройдена.
- `tests/EURUSD_ML_V5_CONFIRMATION.json`: финальная схема с дополнительной моделью,
  отдельные ранее не просмотренные 10000 более ранних свечей из архива 40000.
  Контрольная точность для 1/3/5/15 минут: 54.5% / 52.2% / 51.2% / 49.2%.
  Дополнительная модель не прошла внутренние фильтры и отключилась; строгий
  отбор цели 70% не нашёл. В эту фазу не переносились отобранные по контрольным
  исходам настройки. Названия модели в исходных JSON имеют промежуточную метку v4;
  сама исследованная схема описана полем protocol и данными model_selection.

В отчётах нет API-ключей или данных Telegram. Исследовательский архив остаётся
локально в игнорируемом `artifacts/eurusd-research.db`. Исследование отражает отдельные
периоды внешнего рынка, а не подтверждённую доходность Pocket Option.

Поле `score` в v5 означает предварительную оценку успешности: при активной дополнительной
модели оно может быть ниже 50%. Исходная уверенность направления сохранена отдельно
в `direction_confidence`. Показываемый процент по-прежнему берётся из отдельной калибровки.
