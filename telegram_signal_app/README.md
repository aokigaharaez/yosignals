# Signal Lab — Telegram Mini App

Приватный Telegram Mini App для владельца бота: реальные рыночные свечи,
локальная ML-модель, решения CALL / PUT / ЖДАТЬ, график, журнал и уведомления.

## Быстрый запуск на этом компьютере

Зависимости уже установлены в `.venv`. Откройте PowerShell в папке проекта:

```powershell
.\.venv\Scripts\python.exe -m app.main
```

Или дважды нажмите `start.bat`. Не закрывайте окно сервера.
Откройте http://127.0.0.1:8000. Остановка — Ctrl+C в окне сервера.

При старте выводятся этапы [1/3], [2/3], [3/3]. Дождитесь строки
\`Uvicorn running on http://127.0.0.1:8000\`; до неё Ctrl+C прервёт запуск.
Бот и библиотеки ИИ загружаются в фоне, после открытия веб-сервера.
Пока модель готовится, интерфейс показывает «Ждать» и сообщение о загрузке.
Первый запуск из папки OneDrive может быть медленнее из-за чтения файлов библиотек.

Если нужен только просмотр без подключения к Telegram:

```powershell
$env:BOT_ENABLED="false"
.\.venv\Scripts\python.exe -m app.main
```

Чтобы снова включить бота в том же PowerShell: `Remove-Item Env:BOT_ENABLED`,
затем запустите сервер заново.

## Настройки .env

Существующие значения сохранены. Добавленные пустые поля нужно заполнить:

```dotenv
BOT_TOKEN=токен_вашего_бота
OWNER_TELEGRAM_ID=ваш_числовой_Telegram_ID
TWELVE_DATA_API_KEY=ваш_ключ_Twelve_Data
WEBAPP_URL=https://ваш-домен.example
```

Не публикуйте `.env`. В прежнем `.env.example` был токен: перевыпустите его через
BotFather и обновите `BOT_TOKEN`. Из нового шаблона секрет удалён.

Без Twelve Data работают публичные криптовалютные данные Binance, если источник
доступен в вашей сети. Валютные пары показывают состояние «Нужен API-ключ».
Никаких случайных котировок или подставных прогнозов приложение не создаёт.

После изменения `.env` требуется перезапуск сервера.

## Открытие внутри Telegram

1. Разместите приложение на сервере с публичным HTTPS-адресом или подключите
   HTTPS-туннель к локальному порту 8000. Локальный адрес 127.0.0.1 нельзя использовать
   как WEBAPP_URL: Telegram на телефоне не сможет к нему подключиться.
2. Укажите этот HTTPS-адрес в WEBAPP_URL.
3. Для сервера за reverse proxy установите LOCAL_PREVIEW=false.
   Если нужен внешний bind, задайте HOST=0.0.0.0 и ограничьте порт на уровне сети:
   пользователи должны обращаться через HTTPS-прокси.
4. Запустите один процесс `python -m app.main`. Он обслуживает веб-приложение,
   polling бота и планировщик. Несколько worker-процессов не поддерживаются.
5. Отправьте боту /start в личном чате и нажмите «Открыть Signal Lab».
   При подключении бот также задаёт кнопку меню Mini App.

Доступ разрешён только OWNER_TELEGRAM_ID. Сервер проверяет HMAC-подпись initData
и срок сессии Telegram. LOCAL_PREVIEW разрешает только локальный просмотр рынка;
журнал, запись результатов и автоанализ требуют Telegram-авторизации.
После истечения сессии закройте и откройте Mini App заново.

## Команды бота

- /start — открыть Mini App и помощь.
- /analyze EURUSD 3 — получить и сохранить анализ.
- /watch EURUSD 3 — включить автоанализ одной пары.
- /stop — остановить автоанализ; уже назначенные напоминания сохраняются.
- /stats — результаты, которые вы отметили вручную.

Поддерживаемые активы: EURUSD, GBPUSD, USDJPY, AUDUSD, EURJPY, BTCUSDT, ETHUSDT.
Экспирации: 1, 3, 5, 15 минут. На длинной экспирации модель чаще выбирает «Ждать»,
поскольку независимых примеров для проверки меньше.

Автоанализ сохраняет настройки в SQLite, проверяет выбранную пару примерно раз
в минуту и присылает новые CALL/PUT. Для сохранённых направленных сигналов
есть напоминания перед входом, в момент входа и при закрытии. Доставка зависит от
работы сервера, сети и Telegram; запоздалый сигнал следует пропустить.
Вход в сделку приложение не выполняет.

## Рыночные источники

- **Twelve Data**: минутные OHLC валютных пар, до 1 500 свечей на запрос.
  Требуются API-ключ и соответствующий доступ в тарифе. Проверьте задержку данных
  и условия использования/отображения котировок вашего тарифа.
- **Binance Spot**: BTC/USDT и ETH/USDT через публичный market-data API;
  две страницы истории до 1 500 свечей, ключ не нужен.

Кеш по активу действует 60 секунд. Ошибки и ограничения провайдера также
кешируются на 60 секунд. Автоанализ одной валютной пары может потреблять около
60 запросов в час / 1 440 в сутки; лимиты тарифа могут быть меньше.
Переключение пар расходует дополнительные запросы.

Используются только закрытые свечи. Неверные OHLC, дубликаты, пропуски,
недостаточная история и устаревшие данные обрабатываются явно.
Сигнал блокируется, когда котировки старше MAX_DATA_AGE_SECONDS (90 по умолчанию)
или до предполагаемого входа остаётся меньше 10 секунд.

Цены — внешние рыночные данные, а не поток Pocket Option. Пары к USDT нельзя
считать идентичными брокерским инструментам к USD. Перед использованием
нужно проверить наличие актива и сопоставимость цен. **OTC Pocket Option не
поддерживается:** для него нужен отдельный подтверждённый источник котировок.

## ML-модель

Это обучаемая логистическая регрессия scikit-learn, работающая на сервере;
ключ OpenAI или другой LLM не нужен.

- Модель обучается отдельно для каждой пары и экспирации.
- 10 причинных признаков: изменения цены за 1/3/5/10 свечей, EMA 9/21,
  RSI 14 (простое среднее), тело и диапазон свечи, волатильность, отклонение от EMA.
- Первые 75% пригодных примеров обучают StandardScaler и LogisticRegression.
  Поздние 25% используются для проверки. Цели, пересекающие границу проверки,
  исключены. Проверочные примеры не перекрываются по горизонту.
- Модель прогнозирует направление от входа через одну минуту после закрытия
  анализируемой свечи до окончания выбранной экспирации. Такая же временная
  схема используется в обучающих целях.
- Порог оценки — 60%. Дополнительно проверяется преимущество над постоянным
  базовым прогнозом на отложенной истории, точность от 54% и минимум
  20 сильных проверочных прогнозов.
- Слабая проверка или недостаток данных дают ЖДАТЬ. Модель не обязана
  выдавать сигнал на каждой свече.

Оценка модели **не калибрована как вероятность выигрыша**. Небольшая недавняя
выборка, подбор условий на проверочной истории и меняющийся рынок ограничивают
надёжность оценки. Это исследовательский прототип, не доказанная прибыльная
стратегия. Метрики не включают выплату брокера, исполнение, расхождение котировок
и результаты реальных сделок.

## Журнал и сохранность данных

Новые анализы хранятся в analysis_runs; исходная таблица signals сохранена.
Случайные demo-сигналы и ручное создание из старой версии удалены из интерфейса
и команд. Старые результаты не смешиваются со статистикой ML.

Повторный анализ одной свечи, пары и экспирации не создаёт дубликат.
WIN/LOSS/DRAW можно отметить один раз после закрытия направленного сигнала.
Источник результата — user_reported: это отметка пользователя, не проверка брокера.
В локальном просмотре личный журнал недоступен.

## Установка с нуля

Нужен Python 3.12+ (проверено на Python 3.14 в Windows).

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# Заполните .env. Не перезаписывайте уже настроенный файл.
.\.venv\Scripts\python.exe -m app.main
```

В Linux используйте `python3 -m venv .venv` и `.venv/bin/python`.
SQLite-файл должен храниться на постоянном диске. Для резервной копии остановите
сервер и сохраните файл БД. Не запускайте несколько копий сервера с одним токеном.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
node --check app/static/app.js
```

Тесты проверяют подписи и срок Telegram-сессий, приватность API, целостность свечей,
кеш и лимиты источника, причинность признаков, временные цели модели, устаревшие
данные, дедупликацию, запись результатов и сохранность старой таблицы.
